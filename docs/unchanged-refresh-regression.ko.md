# 동일 응답 재조회 비용 감소

같은 날짜·인증 세션에서 서버의 전체 과업 응답이 같을 때만 기존 목록 객체를 유지합니다. 필드·일지·순서·계층·날짜·세션이 바뀌면 기존 전체 교체 경로를 사용합니다. 초기 부분 교체 실험은 포함하지 않았고, 진단 코드도 제품에 포함하지 않았습니다.

검증 기준은 a7ad72f688c0d81dab8262238d7078ee54b41a80, 최종 검증 코드는 2044f759d56e453264e70378b60ef57750d4bb05입니다. 원래 사용자 이력 및 이전 수정은 유지합니다.

## 확인한 결과

Android 15/API35 x64 에뮬레이터, SwiftShader, 2vCPU·2GiB, 동일한 합성 1,000개 과업과 격리 DB에서 기준판과 최종판을 비교했습니다. 무변경 재조회는 각 3회 중앙값입니다.

| 항목 | 기준 | 최종 |
|---|---:|---:|
| 응답 역직렬화 이후 UI 목록 적용 | 620.524ms | 1.032ms |
| UI 스레드 할당 | 38,087,896바이트 | 477,888바이트 |
| 과정 내 Gen0 수집 | 9회 | 0회 |

네트워크·역직렬화·후속 레이아웃을 모두 포함한 완료 시간이 아닙니다. 변경 저장 후에는 최종판도 최대 314.070ms가 걸렸습니다. 양쪽 모두 1,000행을 생성하므로 가상화 구현이나 모든 스크롤 끊김 해결이 아닙니다.

- 모델 19개와 UI 14개 회귀 검사가 통과했습니다. 동일 객체 유지, 변경·추가·삭제·정렬 시 전체 교체, 선택·확장·미저장 초안 및 날짜 변경을 포함합니다.
- 실제 Gboard에서 650ms 간격으로 합성 한글을 입력·저장한 결과 양쪽 각각 3/3에서 저장 전 화면과 DB 원문이 일치했습니다. 날짜 이동 후 복귀 및 미저장 초안 유지도 확인했습니다.
- 실제 스와이프 2회씩에서 프레임 제출 간격 p95는 기준 31.723–32.066ms, 최종 19.230–20.452ms였습니다. 소프트웨어 GPU의 소수 반복이며 실기기 개선율이나 디스플레이 프레임 누락률로 일반화할 수 없습니다. 33ms대 간격은 남습니다.
- 빠른 입력 파일럿의 자모 분리 실패는 기준판에서도 관측됐습니다. 앱 조합 처리와 자동화 타이밍을 분리하지 못했으므로 미해결이며, 느린 입력 성공으로 완전한 IME 검증을 주장하지 않습니다.

## 재현과 유지보수

저장소에 지정된 .NET SDK로 테스트 프로젝트를 Release 실행하면 모델 검사를, `-- --ui`를 붙이면 UI 검사를 수행합니다. `-- --large-list`는 합성 HTTP와 화면 없는 UI로 대량 목록을 비교합니다. 실제 Android 수치는 별도 에뮬레이터 측정 결과이며 이 명령으로 대체되지 않습니다.

`TaskTreeRefresh`는 모든 저장 필드 및 일지 항목을 비교합니다. DTO에 필드가 추가되면 비교 함수와 회귀 검사도 함께 갱신해야 합니다. 전체 응답 비교·정렬·JSON 처리 비용은 남습니다.

이번 PR 반영에서는 운영 DB, NAS, 실기기 설치, master 및 사용자 작업트리를 변경하지 않습니다. 한글 이력 재작성은 별도 준비 상태이며 이번 기능 커밋을 보존하도록 갱신하기 전 기존 재작성본을 푸시하면 안 됩니다.
