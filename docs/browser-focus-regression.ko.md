# 모바일 브라우저 조합 입력의 필드 이동 보존

## 증상과 원인

아이디를 조합 입력하는 중 비밀번호 칸으로 이동하면 아이디의 preedit가 사라지고 종료 문자열이 새 비밀번호 칸에 전달됐다. 실제 Chrome/Gboard의 격리 업무일지 앱에서 재현했다. 공식 Avalonia 11.3.22도 같은 조합 대상 소유권 부재가 있으며 qa-ime.3만의 신규 결함이라고 단정하지 않는다.

기존 BrowserTextInputMethod는 compositionend를 현재 client와 현재 키보드 포커스로 전달했다. Avalonia는 새 포커스를 지정한 다음 이전 TextBox의 LostFocus와 IME client 교체를 처리한다. 따라서 뒤늦은 네이티브 조합 종료가 새 칸으로 전송될 수 있다.

## 수정

검증용 Avalonia.Browser 11.3.22-qa-ime.6에만 반영했다. 조합 시작 당시 client와 입력 대상을 기억한다. IsFocused=false 알림에서 네이티브 blur를 요청해 TextBox가 선택을 해제하기 전에 조합을 확정한다. 기존 대상의 선택 교체를 보존하고 읽기전용·비활성화·분리된 대상은 새 필드에 우회 입력하지 않는다. 포커스가 같은 일반 경로는 기존 raw 입력 처리를 유지한다.

blur가 동기 종료 이벤트를 주지 않는 fallback에서는 마지막 preedit를 기존 대상에 확정하고 이전 네이티브 DOM을 교체한다. 그 DOM의 지연 종료가 새 조합을 오염시키지 않도록 분리한다. 구독과 캡처는 종료 전에 해제한다. 실제 검사한 Gboard에서는 blur 호출 안에서 compositionend가 발생했다. 비동기 IME의 종료 시 자동교정 문자열이 마지막 preedit와 다른 경우까지 실제 검증한 것은 아니다.

앱 자체 HTML 편집기 우회는 추가하지 않았으며 네이티브 Android·데스크톱 패키지, backend·DB 모델·API는 바꾸지 않았다.

## 검증 결과

- 공식11.3.22/qa-ime.3: 초기 합성 포커스 행렬 각각1/8. 조합 중 이동7개가 실패하고 조합 종료 후 이동1개는 통과했다.
- qa-ime.3 실제 앱: Gboard 합성 한글 아이디가 비밀번호로 이동하는 증상을 재현했다.
- 공식 버전 실제 영문3회는 모델에 원문이 남지 않았고 qa-ime.3은 같은 Gboard 조건3/3 통과했다. 영문 실패를 모두 동일한 필드 이동 원인으로 단정하지 않는다. 사용자 영상의 삼성 키보드와 Gboard를 동일 환경으로 취급하지 않는다.
- 최종 후보 합성 검사: 포커스8/8, 정역방향 선택 교체·읽기전용·비활성화6/6, 이전 DOM 지연 종료4/4. 총18/18.
- 최종 후보 실제 Gboard 화면 키 탭·입력칸 탭: 한글6/6, 영문3/3. 단일행·암호·여러 줄 칸 전환 포함.
- 실제 업무일지의 격리 일반 QA 계정에서 화면 키보드로 아이디·암호를 입력하고 로그인200, 사용자 조회200, 앱 화면 진입 확인. DOM 값 주입/API 로그인으로 이 검사를 대체하지 않았다. 전송값은 fixture와 일치했다. 초기 후보 첫 시도401은 성공으로 세지 않으며 당시 입력 일치 계측이 없어 원인을 확정하지 않는다.
- 같은 계정에서 실제 Gboard 한글·공백·연속 Enter 비고를 앱 저장 버튼으로 저장, SQLite 원문 일치와 날짜 이동 후 재조회 확인.
- 기존 UI14/14, 가짜 HTTP 모델17/17, Browser JS13/13 통과. 11.3.22 backport 라이브러리와 실제 업무일지 WASM 빌드 성공.
- 독립 최소 재현 및18개 합성 회귀는 vendor/avalonia/tests/focus-repro에 보존했다.

## 범위와 제한

검사는 Android 에뮬레이터 Chrome/Gboard와 폐기용 로컬 SQLite에서 수행했다. 운영 공개 사이트에서 실제 타이핑 로그인 성공을 검증한 것은 아니다. 승인된 운영 QA 계정이 없어 실제 사용자 자격 증명을 사용하지 않았다. 사용자 영상은 실제 프레임을 확인했으나 영상·입력값은 저장소에 포함하지 않는다.

삼성 키보드 실기기 재검사, 모든 IME의 비동기 자동교정, 전체 PC 선택29행렬 재실행은 미검증이다. Windows 및 네이티브앱 실행 검사를 이번 웹 수정에서 반복하지 않았다. upstream main 소스에도 대응 수정은 준비했지만 설치된 .NET11 컴파일러의 Microsoft.CodeAnalysis 5.12.0.0 로딩 실패로 전체 upstream 빌드가 막혔다. 이 장애를 11.3.22 앱용 backport 빌드 실패로 혼동하지 않는다. 공식 upstream PR은 사람 검토 전 보류한다.

이 문서의 작성은 NAS 배포 또는 실기기 설치 완료를 뜻하지 않는다. 기존 배포 아티팩트는 덮어쓰지 않는다.
